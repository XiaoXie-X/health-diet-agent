## 💡 为什么做这个

使用通用 AI 助手咨询饮食问题时，存在两个核心痛点：

| 痛点 | 表现 | 本产品的解法 |
|------|------|--------------|
| **数据幻觉** | AI 随口编造食物热量，数字看着精确其实是编的 | 营养数据强制走本地数据库查询（Function Calling），未收录食物由模型估算但**必须标注"估算值"**，不冒充精确数据 |
| **无记忆** | 每次对话都要重新交代身高体重、过敏忌口 | 用户画像持久化存储（SQLite），跨会话记住你的身体数据和偏好 |

## ✨ 核心功能

- 💬 **对话式营养咨询** —— 营养师"小蟹"人设，朋友式口吻，多轮上下文
- 🔍 **三种智能工具** —— 营养查询 / 每日热量计算（BMR·TDEE）/ 联网搜索（Tavily）
- 🧠 **用户画像记忆** —— 年龄、身高体重、目标、过敏忌口自动采集与更新
- ⚡ **流式输出 + 阶段播报** —— "正在思考 → 联网搜索：XX → 生成中"，等待不再黑盒
- 🛡️ **可信设计** —— 估算值明确披露、疾病饮食建议就医、拒绝推荐极端饮食方式

## 🏗️ 技术架构

```
用户 ⇄ Next.js 前端（daisyUI 聊天界面，流式渲染）
         │  SSE（Server-Sent Events）
         ▼
      /api/chat（对话编排层）
         │
         ├─⬀ DeepSeek API（人设提示词 + Function Calling）
         │        │ 判断需要工具时
         │        ▼
         ├─⬀ 本地营养数据库（12种食物精确值）
         ├─⬀ 热量计算引擎（Mifflin-St Jeor 公式）
         ├─⬀ Tavily 联网搜索
         └─⬀ 估算兜底（未收录食物 → 二次调用模型并标注不确定性）
         │
         ▼
      SQLite（用户画像 + 对话历史）
```

**关键技术决策**：

| 决策 | 理由 |
|------|------|
| Function Calling 而非让模型直接回答 | 大模型背食物热量经常幻觉，精确数据必须走数据库 |
| SSE 状态事件设计 | 工具调用链路需 8-10 秒，无反馈的等待=流失，分阶段播报降低焦虑 |
| 模型估算必须标注"估算值" | 承认不确定性是可信 AI 的底线设计 |
| 前后端双层行缓冲 | SSE 数据被 TCP 分包切断时防丢字 |

## 📈 产品迭代

**提示词四轮数据驱动迭代**（v4 由人工评测驱动）：

| 版本 | 迭代内容 | 针对问题 |
|------|----------|----------|
| v1 | 基础人设 | — |
| v2 | 输出格式约束（禁 Markdown）+ 工具使用策略 | 回复带星号、该查不查 |
| v3 | 专业约束 + 安全护栏 + 对话引导 + 弹性长度 | 编数据、疾病边界、回复冗长 |
| v4 | 工具回路重构（结果回传模型二次生成）+ 搜索降级兜底 + 估算份量换算 + 查询类极简回复 | 15 题人工评测暴露的 3 个 bad case |

## 📊 效果评估

上线后进行了一轮 **15 题人工评测**（覆盖数据库命中、估算兜底、联网搜索、多轮记忆、过敏约束、医疗边界、极端饮食拦截等场景，1-5 分制）：

> **平均分 4.2 / 5 · 满意率（≥4 分）80%（12/15）**

评测暴露 3 个 bad case，均已完成定位与修复：

| Bad Case | 现象 | 根因 | 修复 |
|----------|------|------|------|
| 搜索链路架构缺陷 | 问"最新膳食指南"只回一句"没有找到相关信息"；搜索成功时又整段粘贴网页原文 | 工具结果未回传模型，由代码直接拼接成最终回复——模型没有机会综合资料、也无法在失败时兜底 | 重构为"工具结果 → 模型二次生成"标准回路；搜索失败自动降级为既有知识作答并注明时效性；搜索结果正文截断防倾倒 |
| 估算份量错位 | 问"螺蛳粉"只给每 100g 数据，用户预期是"一碗" | 估算兜底只输出单位营养，无份量换算 | 估算输出追加常见份量换算（一碗/一份约多少热量） |
| 简单问题偏长 | "鸡蛋热量"回复完整营养列表 | 弹性长度指令对纯查询类不够具体 | 增加"纯查询一行答完"规则 |

修复后复测通过（本地双场景 + 线上验证）：搜索正常时输出结构化回答并附来源链接；搜索服务异常时自动降级为既有知识作答并注明时效性。

**工程历程**：25 个语义化提交，从 MVP 到上线全程可回溯（`git log` 可查）。

```bash
cd health-diet-agent
npm install

# 创建 .env.local 填入：
# DEEPSEEK_API_KEY=你的key

npm run dev  # 打开 http://localhost:3000
```
